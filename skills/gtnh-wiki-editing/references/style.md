# 推荐编辑规范

返回[技能首页](../SKILL.md)。本页是写条目、改页面时的约定；标注「维护者」的小节另外适用于模板、模块和零件的维护。

## 写作

适用：所有编辑者。

- 使用简体中文，句子短而直接；先给结论，再给条件和数字。
- 物品、方块、维度一律用 `{{Item|名称}}`，不要只写纯文字名称。
- 否定说法统一为「**主语**不会……」「**主语**无法……」，主语加粗，例如「**水**无法进行通用矿物处理」。不要写「当前数据中没有」「目前数据集不包含」这类说法。
- 数值写明单位（tick、秒、L、EU/t），换算结果与原始值一起给出，例如「每 tick 2 点，即每秒 40 点」。

## 条目

适用：所有编辑者。

- 条目页使用 `{{条目/<类型>}}` 模板，类型与参数见[维基技术现状](wiki-tech.md#条目模板与数据库的关联)。只介绍机制、没有关联物品的页面使用 `{{条目/Infobox}}`。
- **页面名**就是物品、材料或维度的精确中文名。需要消歧义时加全角括号后缀，例如「锻造锤（机器）」「锻造锤（工具）」，再用消歧义页连接。
- 标题里不能出现的字符 `[ ] { } | < >` 一律替换为短横线 `-`。
- 一组同类物品（如各种氧气罐、各阶重型装甲板）合并成一个集合条目：主关联留空，用副关联逐项列出，并用 `信息-副关联页签` 写简短的页签名。每个副关联的中文名都要建立重定向指向本条目。
- 单方块机器使用 `{{条目/可获得对象}}`，并填写 `索引-分类关联=单方块机器`。
- 注释、导航等通用章节由模板自动生成，不要手写 `章节-注释`、`章节-导航`。
- 能放进标准章节（简介、用途、指南、历史）的内容不要另开「额外章节」。
- `索引-内容版本` 填你实际核对过的游戏版本。已移除的物品保留条目，用 `索引-数据版本` 指向它存在的版本，并填写 `索引-失效版本`。
- 获取章节显示「没有配方」时，先检查 `控制-合成表类型` 是否漏填了实际的配方类型，再判断是不是数据缺失。

## 链接

适用：所有编辑者。

- 链接写到页面的实际标题，不要链到重定向；页面改名后，把指向旧标题的链接、重定向和导航一起更新。
- 外部来源优先链接 GTNewHorizons 组织的源码文件，以文件名作为显示文字；条目信息框用 `属性-源代码`、`属性-英文维基` 填写。
- 关键数字和机制用 `<ref>` 注明来源，写清是哪个文件、哪个方法。

## 导航

适用：所有编辑者，数据表格式见[维基技术现状](wiki-tech.md#分类关联与导航)。

- 新建条目后，把它加进所属导航的数据表 `模块:Navbox/<名称>`；导航中的链接要与页面全名完全一致，否则条目会提示 `navbox-missing`。
- 导航项的显示名尽量与页面名相同；只有重名时才另写 `link`。

## 查证

适用：所有编辑者。

- 事实以游戏导出数据和源码为准：数据看 `Data:` 页面或用模块查询，机制看 GitHub 上 GTNewHorizons 的源码。
- 查不到依据的说法不要写；从旧版本页面恢复的内容要注明来源和时效。
- 引用他人在社区中的说法前，先用数据或源码核对。

## 维护者规范

适用：维护者。

- 模板的说明与示例写在模板页的 `noinclude` 区域；草稿放在 `Project:沙盒/<用户名>/…` 下。
- 模板页上的示例如果会让模板嵌入自己，就先用 `<pre>` 写出源码，再在安全的地方给出等价的实际调用。
- 参数风格沿用同类模板已有的写法，新增的别名要写进模板文档。
- Lua 模块的输出要确定、可重复；能在服务端渲染的内容，不要依赖前端脚本。
- 新建零件默认保持禁用；只需要样式时不要引入 JavaScript。
- 零件先检测页面上稳定的入口元素，再加载较重的脚本和样式；同一份样式只放在一个地方，不要在多处复制。
- 大型、客观的数据（数值表、配方表、常量）放在 `Data:` 页面，方便单独更新；界面文字和少量标签留在零件或模块里。零件读取 `Data:` 页面失败时，要显示简短的错误提示，并在有默认数据时继续可用。
- 修改公共模块或数据表前，先在几个代表性页面上预览；保存后清除这些页面的缓存并核对。
- 大批量修改使用机器人账号并带 `bot=1`，做法见[自动化编辑流程](automation.md#批量与机器人编辑)。
- 数据结构、版本别名或数据集有变化时，同步更新 [Project:Database](https://gtnh.huijiwiki.com/wiki/Project:Database)。
